# 고해상도 영역 캡처 확대 현상 검토

작성일: 2026-11-02

## 보고된 현상과 기대 동작

사용자 보고: “1980 이상의 해상도에서는 캡처 시 프로그램들이 상당히 커진 상태로 보인다.” 정확한 화면 해상도와 Windows 배율은 아직 확인되지 않았다.

영역 캡처를 시작해도 화면에 보이던 프로그램의 크기와 위치가 유지되어야 한다. 사용자는 그 상태에서 영역을 지정하고, 선택한 실제 화면 픽셀을 결과 이미지로 받아야 한다. 선택 안내용 커서 확대창은 이 현상과 구분한다.

## 코드에서 확인한 내용

- `src/ASnapdo/Program.cs`: `ApplicationConfiguration.Initialize()`로 WinForms를 초기화한다.
- `src/ASnapdo/ASnapdo.csproj`: `ApplicationHighDpiMode`를 명시하지 않는다. 실제 적용 DPI 모드는 생성 코드와 Windows 실행 상태에서 추가 확인해야 한다.
- `src/ASnapdo/Services/CaptureService.cs`: 전달받은 영역 크기의 비트맵에 `Graphics.CopyFromScreen`으로 화면을 복사한다.
- `src/ASnapdo/UI/SelectionForm.cs`: `SystemInformation.VirtualScreen`으로 전체 데스크톱 영역을 얻고, 같은 영역을 캡처해 선택 창의 Bounds로 사용한다. `AutoScaleMode.None`을 지정하며 배경은 `DrawImageUnscaled`로 그린다.
- 선택 창의 마우스 좌표를 그대로 비트맵 잘라내기에 사용한다. 이 구조는 화면 좌표, 선택 창 클라이언트 좌표, 캡처 비트맵 픽셀이 일치한다는 전제가 있다.
- `tests/ASnapdo.Smoke/Program.cs`의 `TestSelectionOverlay`는 합성 이미지의 선택 좌표, 음수 데스크톱 원점, 결과 픽셀을 검사한다. 실제 고해상도 화면과 혼합 DPI 모니터의 캡처 정합성을 검증하지는 않는다.

## 원인 가설

해상도 자체보다는 Windows DPI 가상화 또는 모니터별 배율 차이로 좌표계가 어긋나는 문제를 우선 의심한다. 특히 125~200% 배율이나 서로 다른 배율의 다중 모니터에서 캡처 픽셀과 표시 좌표가 다르게 해석될 가능성이 있다.

`AutoScaleMode.None`은 폼의 자동 크기 조절 설정이다. 이것만으로 프로세스나 창의 DPI 인식 수준과 Windows의 비트맵 확대 처리가 해결되었다고 볼 수 없다. 반대로 `DrawImageUnscaled`가 있다는 사실만으로 실제 화면 표시까지 1:1이라고 확정할 수도 없다.

현재는 코드 검토에 따른 가설이며, Windows에서 증상을 재현하거나 원인을 확정한 상태가 아니다.

## 수정 방향

1. 실제 프로세스·선택 창의 DPI 인식 모드, 모니터별 배율, 물리 해상도, 가상 화면 영역, 캡처 비트맵 크기, 선택 창 클라이언트 크기를 확인한다.
2. 창 생성 전에 모니터별 DPI 인식(`PerMonitorV2`)을 적용하는 방안을 검토한다. 기존 편집기와 설정 창의 레이아웃에 미치는 영향도 확인한다.
3. 화면 캡처·선택 창 배치·포인터·잘라내기 좌표가 동일한 물리 픽셀 기준을 사용하도록 정리한다. 실제 좌표계를 확인하기 전 배율을 일괄 곱하거나 나누는 보정은 적용하지 않는다.
4. 혼합 DPI 환경에서 한 개의 전체 데스크톱 선택 창이 정확히 표시되는지 확인한다. 문제가 남으면 모니터별 선택 창과 공통 화면 좌표를 사용하는 구조를 검토한다.
5. 선택 안내선, 어두운 배경, 확대창이 결과 이미지에 포함되지 않는 기존 동작을 유지한다.

## Windows 검증 항목

| 환경 | 확인할 내용 |
| --- | --- |
| 1920×1080, QHD, 4K / 배율 100% | 캡처 시작 전후 프로그램 크기와 위치 유지 |
| QHD·4K / 배율 125%, 150%, 200% | 배경 확대·잘림 없이 화면 가장자리까지 선택 가능 |
| 서로 다른 해상도·배율의 모니터 | 각 모니터에서 시작 및 모니터 경계를 넘는 선택 정확성 |
| 보조 모니터가 주 모니터의 왼쪽·위쪽 | 음수 화면 좌표와 결과 잘라내기 정확성 |
| 편집기를 다른 배율의 모니터로 이동한 뒤 캡처 | 이전 모니터의 DPI가 선택 화면에 잘못 적용되지 않는지 확인 |
| 전역 단축키·트레이·편집기에서 영역 캡처 | 진입 경로마다 동일한 화면 표시와 선택 결과 |
| 전체 화면 캡처 | 영역 캡처와 동일한 물리 픽셀 기준인지 확인 |

고정된 화면의 식별 가능한 경계와 픽셀 패턴을 이용해 캡처 전후 위치를 비교한다. 선택 영역의 가로·세로 표시값과 PNG 크기가 일치하고, 결과 이미지가 원본의 해당 픽셀과 일치해야 한다. Esc·우클릭 취소, Shift 정사각형 선택도 회귀 확인한다.
